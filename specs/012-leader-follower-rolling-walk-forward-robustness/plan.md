# Implementation Plan: Leader-follower rolling walk-forward robustness

**Branch**: `012-leader-follower-rolling-walk-forward-robustness` | **Date**: 2026-03-24 | **Spec**: [spec.md](./spec.md)

## Summary

Add **rolling walk-forward robustness evaluation**: generate many chronological train → validate → (optional) test splits over one overall range, evaluate the same modest parameter grid or explicit candidate list on **each** split via existing `compute_paper_trading_metrics`, persist per-split metrics and cross-split aggregates, rank by **`rolling_robustness_v1`** (median validation return and consistency, not peak single-split return). CLI-first + read-only APIs under `/api/leader-follower/robustness/`, new SQLite tables (do not overload optimization tables).

## Technical Context

**Language/Version**: Python 3.11
**Primary Dependencies**: FastAPI, SQLAlchemy, Pydantic, Typer (existing stack)
**Storage**: SQLite; new tables `leader_follower_robustness_runs`, `leader_follower_robustness_split_results`, `leader_follower_robustness_aggregates`
**Testing**: pytest; unit tests for split math and ranking; API tests with in-memory SQLite
**Target Platform**: Linux (Fedora per project preference); FastAPI backend
**Project Type**: Brownfield web API + CLI (`backend/app`)
**Performance Goals**: Bounded work: `splits × candidates` capped via config; fail fast with clear errors
**Constraints**: Reuse `010` grid expansion/keys and `011` paper metrics; PRD structured errors; no silent failures
**Scale/Scope**: Research tooling; modest grids (same order of magnitude as `leader_follower_optimization_max_grid_points`)
